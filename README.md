# 🏀 NBA 3D Playbook

NBA에서 자주 쓰이는 공격 작전 10가지를 **3D 코트 위에서 단계별로 재생하며** 배우는 인터랙티브 플레이북입니다.
선수들이 실제로 움직이고, 코트 바닥에는 코치들이 쓰는 전술판 표기(컷·드리블·패스·스크린)가 그려지며, 단계마다 "지금 무슨 일이 일어나는지"를 한국어로 설명합니다.

**▶ 바로 보기: https://hpotty36.github.io/nba-3d-playbook/**

![NBA 3D Playbook 미리보기](docs/preview.jpg)

## 수록 작전

| # | 작전 | 분류 | 난이도 | 한 줄 요약 |
|---|------|------|:---:|------|
| 1 | 픽 앤 롤 (Pick and Roll) | 온볼 스크린 | ●○○ | 스크린 → 돌파 → 롤맨에게 패스, NBA의 기본 2인 공격 |
| 2 | 픽 앤 팝 (Pick and Pop) | 온볼 스크린 | ●○○ | 스크리너가 림 대신 3점 라인으로 빠져 슈팅 |
| 3 | 스페인 픽앤롤 (Spain P&R) | 온볼 스크린 | ●●● | 픽앤롤 + 롤맨 수비에게 거는 백스크린 |
| 4 | 혼즈 (Horns) | 온볼 스크린 | ●●○ | 엘보의 두 빅맨, 하이 픽앤롤 → 하이-로우 |
| 5 | 플로피 (Floppy) | 오프볼 스크린 | ●●○ | 림 아래 슈터가 싱글/스태거 스크린 중 선택 |
| 6 | 엘리베이터 도어 (Elevator Doors) | 오프볼 스크린 | ●●○ | 두 스크리너가 문을 닫듯 수비를 가둠 |
| 7 | 아이버슨 컷 (Iverson Cut) | 오프볼 스크린 | ●○○ | 자유투 라인 위를 가로지르는 엔트리 컷 |
| 8 | 시카고 액션 (Chicago) | 오프볼 스크린 | ●●○ | 핀다운 스크린 → 드리블 핸드오프 |
| 9 | 해머 (Hammer) | 모션 & 드라이브 | ●●○ | 베이스라인 돌파 + 약한 쪽 스크린 → 코너 3점 |
| 10 | 스플릿 액션 (Split Action) | 모션 & 드라이브 | ●●● | 포스트 엔트리 후 공 없는 두 선수의 스크린 |

작전마다 **단계별 진행 · 이럴 때 쓴다 · 핵심 포인트 · 수비는 어떻게 막나 · 대표 사례**가 함께 들어 있습니다.

## 사용법

| 조작 | 기능 |
|------|------|
| `Space` | 재생 / 일시정지 |
| `←` `→` | 이전 / 다음 단계 |
| `↑` `↓` | 이전 / 다음 작전 |
| `1`–`5` | 카메라: 코치 · 중계 · 전술판(탑뷰) · 엔드라인 · 공 추적 |
| `D` `N` `L` | 수비 · 전술판 표기 · 번호 라벨 켜고 끄기 |
| `R` | 처음부터 다시 |
| 마우스 드래그 / 휠 | 자유롭게 회전 · 확대 |

- 타임라인을 드래그하면 원하는 순간을 멈춰서 볼 수 있습니다.
- 오른쪽 패널의 단계를 누르면 그 단계로 바로 이동합니다.
- 주소 뒤에 `#hammer`처럼 작전 id를 붙이면 그 작전으로 바로 열립니다.
- `?cam=top&t=3.5#hammer`처럼 카메라와 시점(초)을 지정하면 그 장면에서 멈춘 채로 열립니다. 특정 순간을 공유할 때 편합니다.

### 전술판 표기

| 표기 | 의미 |
|------|------|
| 흰 실선 + 화살표 | 컷(공 없이 이동) |
| 노란 지그재그 | 드리블 |
| 주황 점선 | 패스 |
| 하늘색 선 + T자 | 스크린 |
| 분홍 점선 | 슛 |

공격은 주황색 원형 번호(①–⑤), 수비는 파란색 `X1`–`X5`로 표시합니다. 스크린을 거는 순간에는 스크리너 앞에 반투명한 "벽"이 나타납니다.

## 로컬에서 실행

빌드 과정이 없는 정적 사이트입니다. ES 모듈을 쓰기 때문에 파일을 더블클릭하지 말고 간단한 웹 서버로 여세요.

```bash
python -m http.server 8000
# 또는
npx serve .
```

그다음 브라우저에서 `http://localhost:8000` 을 엽니다.

## 프로젝트 구조

```
index.html            레이아웃, Three.js import map
css/style.css         UI 스타일 (데스크톱 3단 / 모바일 1단)
js/main.js            앱 진입점: 장면 구성, 재생 루프, UI 연결
js/engine.js          작전 데이터 → 시간 t에 대한 결정적 타임라인 (선수·수비·공 위치)
js/court.js           NBA 규격 하프코트(캔버스 텍스처)와 골대
js/players.js         마네킹 선수 모델, 포즈(달리기·수비·스크린·슛), 공
js/notation.js        바닥에 그리는 전술판 표기
js/camera.js          카메라 프리셋과 전환
js/plays/*.js         작전 정의 (작전 하나 = 파일 하나)
docs/design.md        설계 메모
```

## 작전 추가하기

`js/plays/` 에 파일을 하나 만들고 `js/plays/index.js` 에 등록하면 됩니다. 좌표 단위는 피트(ft)입니다.

- `x`: 왼쪽 사이드라인 `-25` ~ 오른쪽 사이드라인 `25` (공격 방향 기준 왼쪽이 음수)
- `z`: 베이스라인 `0` ~ 하프라인 `47`, 림 중심은 `(0, 5.25)`
- 자주 쓰는 자리: 탑 `[0, 31]`, 윙 `[±18, 22]`, 코너 `[±23, 3.5]`, 엘보 `[±8, 19.5]`, 블록 `[±9, 8]`

```js
export default {
  id: 'my-play', name: '내 작전', en: 'My Play',
  category: '온볼 스크린', difficulty: 1,
  summary: '...', when: '...', keys: ['...'], famous: '...',
  counters: [{ name: '스위치', desc: '...' }],

  start: { o1: [0, 32], o2: [-23, 3.5], o3: [23, 3.5], o4: [-19, 22], o5: [8, 18] },
  ball: 'o1',
  steps: [
    {
      title: '스크린 세팅',
      dur: 1.6,                                   // 단계 길이(초)
      text: '[5]가 [x1]에게 스크린을 겁니다.',      // [1] = 공격 칩, [x1] = 수비 칩, **굵게**
      move: {
        o5: [[2.6, 28.6]],                        // 경유점 배열 (시작점은 현재 위치)
        o1: { path: [[-1.8, 32.6]], t: [0.25, 0.85] }, // t: 단계 안에서 움직이는 구간(0~1)
      },
      screens: [{ by: 'o5', face: [-1.5, 29.2] }], // face: 스크린이 향하는 지점
      def: {
        d1: { lag: 0.9 },                         // 반응 지연(스크린에 걸린 느낌)
        d5: { path: [[3, 17.5]] },                // 수비 경로 직접 지정
        // guard: 'o5' (스위치), sag: 0 (도움 수비 없이 자기 선수만)
      },
      ball: [
        { type: 'pass', to: 'o5', at: 0.3 },      // pass | bounce | lob | skip | handoff
        { type: 'shot', at: 0.7, pts: 2, kind: 'dunk' }, // kind: jumper | layup | dunk
      ],
    },
  ],
};
```

수비는 따로 지정하지 않으면 자기 선수와 림 사이에 서고, 공에서 먼 수비는 도움 수비 위치로 처지는 규칙에 따라 자동으로 움직입니다.

## 기술

- [Three.js](https://threejs.org/) r160 (CDN, import map). 번들러나 빌드 도구 없음
- 코트 라인과 나무 바닥은 캔버스로 그린 텍스처, 선수는 기본 도형으로 만든 마네킹
- 모든 위치는 시간 t의 순수 함수라서 타임라인을 앞뒤로 자유롭게 넘길 수 있음
